D03 中断架构：主中断、慢速任务、标定任务、故障快速通路

模块 D · 嵌入式落地实战 · 第 3 节

第一部分：小节基础

链路位置软件运行时结构：决定每段代码在什么时刻、以什么优先级执行
输入 / 输出输入：功能列表与时间要求；输出：中断 / 任务划分、优先级、数据交换机制
工程价值FOC 主中断不能被阻塞、不能超时；慢任务与通信不能破坏中断数据一致性
上下游依赖上游 B05、B06；下游 D04、D08、C12
适用角色MCU 底层、软件架构
前置数学依赖无（时间预算计算）
① 为什么需要不同功能的时间尺度相差 4 个数量级（2 µs 硬件保护、50 µs 电流环、1 ms 速度环、100 ms 热模型），必须分层调度。
② 量产怎么做硬件故障 → PWM 硬件关断（无需 CPU）；ADC 完成中断（最高软件优先级）跑 FOC；1 ms / 10 ms 周期任务（RTOS 或定时器中断）；XCP / CAN 在低优先级处理。
③ 如何证明最坏执行时间（WCET）测量、CPU 负载统计、中断抖动测量、数据一致性代码审查与压力测试。

第二部分：前置条件

  • MCU 中断优先级与嵌套配置（Cortex-M NVIC），是否使用 RTOS / AUTOSAR OS。
  • 各功能的周期与最坏执行时间估计。
  • 不满足：XCP 读写、Flash 操作、长时间关中断阻塞 FOC 主中断 → 电流环周期性失控。

第三部分：核心原理与公式

层级触发周期内容优先级
硬件保护比较器 / 驱动故障—PWM 故障输入直接关管硬件（无需 CPU）
故障中断PWM 故障标志事件记录、状态机置 FAULT最高
FOC 主中断ADC 转换完成50 µs采样换算、角度、Clarke/Park、电流环、SVPWM、快速诊断高
2 kHz 任务主中断分频500 µs弱磁环、MTPA 查表（可放 1 ms）主中断内分频或中优先级
1 ms 任务定时器 / OS1 ms速度 / 位置环、给定生成、测速、诊断去抖、状态机中
10 ms / 100 msOS10~100 ms温度、热模型、降额、NVM、通信信号低
后台空闲—XCP 协议处理、自检最低
【理论公式】 CPU 负载 U = Σ (Ci / Ti)；主中断负载 = C_foc / 50 µs 示例 【案例假设】：C_foc = 20 µs → 40%；1 ms 任务 150 µs → 15%；其余 10% → 总 65%，余量 35% 单调速率调度可调度性（Liu & Layland 上界，n 个任务）：U ≤ n·(2^(1/n) − 1)（充分条件，n = 3 时 0.78） 跨层数据：单个对齐 32 位读写原子；多变量用双缓冲 / 序号校验 / 短时关中断
动画在演示什么：2 ms 时间轴上的执行情况：FOC 主中断（每 50 µs）、1 ms 任务（被主中断抢占后继续）、后台 XCP。若某段代码关中断，会推迟主中断。
拖动滑块：增大主中断执行时间或 1 ms 任务时间，CPU 负载上升；「关中断时长」超过主中断剩余余量时，主中断被推迟（红色）——这意味着采样到更新的延迟变化，电流环出现抖动。
正常：主中断准时、负载有余量。异常：红色推迟 / 超载。

第四部分：嵌入式实现步骤

  1. NVIC 优先级：PWM 故障 > ADC（FOC）> 定时器（1 ms）> 通信。
  2. 主中断只做确定性计算：禁止 Flash 写、禁止阻塞调用、禁止可变长度循环。
  3. 跨任务数据：慢任务 → 中断（给定、标定量）用双缓冲 + 「发布」标志；中断 → 慢任务（测量值）用快照结构。
  4. 关中断临界区 < 数 µs，并计入主中断抖动预算。
  5. 执行时间监控：每个任务入口出口时间戳，记录最大值并通过 XCP 读出（B06）。

第五部分：仿真与波形预期

  • 示波器 GPIO：主中断方波稳定 20 kHz、宽度稳定；1 ms 任务方波被切成多段（抢占）属正常。
  • 主中断开始时刻抖动 < 1 µs；若有偶发推迟 → 查关中断代码。

第六部分：EPS 案例实现

/* 慢任务 → 中断：双缓冲发布给定（避免中断读到半更新的 id/iq 对）*/
typedef struct { q15_t idRef, iqRef; } REF_tst;
static REF_tst s_refBuf[2];
static volatile uint8_t s_refIdx = 0u;           /* 中断读取的缓冲区下标 */

void Ref_Publish_1ms(q15_t idRef, q15_t iqRef)   /* 1 ms 任务调用 */
{
    uint8_t w = (uint8_t)(s_refIdx ^ 1u);         /* 写另一块 */
    s_refBuf[w].idRef = idRef;
    s_refBuf[w].iqRef = iqRef;
    __DMB();                                      /* 保证写入顺序 */
    s_refIdx = w;                                 /* 单字节写入原子：发布 */
}

void Ref_Fetch_Isr(void)                          /* FOC 主中断调用 */
{
    const REF_tst *r = &s_refBuf[s_refIdx];
    gFoc.idRef = r->idRef;
    gFoc.iqRef = r->iqRef;
}

/* 主中断分频：2 kHz 弱磁 */
void FOC_FastLoop_Isr(void)
{
    static uint8_t s_div = 0u;
    /* ... 采样、变换、电流环、SVPWM（B03）... */
    if (++s_div >= 10u) { s_div = 0u; gFoc.idRef = FOC_FieldWeakenAdjust(gFoc.idRefMtpa); }
}

双缓冲在「慢任务写一次、中断读多次」时可靠；若慢任务写入周期短于中断读取周期（不会发生于本例），需要更复杂的三缓冲或序号机制。

第七部分：高频调试问题

【高频故障】XCP 测量变量多时电流环抖动
现象
CANape 加入大量 DAQ 信号后电流出现周期性扰动。
可能根因
XCP DAQ 采集在主中断中执行或长时间关中断拷贝。
排查
测主中断执行时间随 DAQ 信号数量的变化。
修复
DAQ 事件放到低优先级或限制主中断事件中的信号数量（D08）。
验证
满配 DAQ 下主中断 WCET 仍有余量。
【高频故障】偶发 iq 给定「跳一下」
现象
id/iq 给定偶发出现不成对的组合（id 新、iq 旧）。
可能根因
慢任务直接写全局变量，中断在两次写之间读取。
排查
代码审查跨上下文变量。
修复
双缓冲发布。
验证
压力测试无复现。
【高频故障】NVM 写入时电机抖一下
现象
保存标定 / 故障记录时电流异常。
可能根因
Flash 擦写期间从同一 Flash 块取指令 / 关中断，主中断被延迟。
排查
GPIO 测主中断间隔。
修复
使用独立 Data Flash / EEPROM 仿真区，关键中断代码放 RAM 执行，或只在停机时写。
验证
写入期间主中断间隔不变。

第八部分：工程踩坑

  • 在主中断里调用 printf / 日志函数。
  • 浮点上下文保存：Cortex-M4F 中断使用 FPU 时的惰性压栈会增加中断延迟，需计入。
  • 主中断依赖 ADC 完成中断，而 ADC 被其他功能（温度采样）插入转换，导致中断时刻漂移。
  • 【风险红线】看门狗只在后台喂：主中断死循环时后台仍在运行喂狗，看门狗失效。应由多层任务共同签到后喂狗。

D04 代码架构：FOC 结构体划分、环间数据流、状态机

第一部分：小节基础

链路位置软件静态结构：模块划分、数据结构、运行状态
输入 / 输出输入：功能需求、AUTOSAR / 非 AUTOSAR 平台；输出：模块接口、结构体、状态机

① 为什么需要FOC 链路 10+ 个模块、100+ 个标定量，没有清晰结构就无法单元测试，也无法让标定工程师理解。
② 量产怎么做按「硬件抽象 / 算法 / 应用」分层；算法模块纯函数化（输入结构 → 输出结构）；单一全局运行数据结构 + 标定结构；明确状态机。
③ 如何证明模块单元测试覆盖率、状态机转移测试（含非法转移）、代码静态分析（MISRA）。

第二部分：前置条件

  • 平台约束：是否 AUTOSAR（若是，电机控制常以复杂驱动 CDD 形式实现，与 RTE 接口交互 【待核对：以项目架构为准】）。
  • 编码规范：MISRA C、命名规则（本教程：g 前缀全局、Cal_ 标定、s_ 静态）。

第三部分：核心原理与公式

分层与模块

层模块职责
硬件抽象（HAL）Pwm_*, Adc_*, Res_*（旋变）, Gpio_*寄存器访问、触发配置，不含算法

状态机（EPS 电机控制层）

【暂无可交互动画】状态机用静态图 + 转移表更清晰。

转移条件动作
INIT → OFFSET_CAL供电稳定、驱动就绪、转速 ≈ 0PWM 关，开始累加
OFFSET_CAL → READY校准完成且范围合法写偏移；失败 → FAULT
READY → RUN_TORQUE上层使能 + 无故障 + 角度有效PI 清零 / 预置、前馈按当前转速初始化、PWM 使能
RUN_TORQUE → RUN_SENSORLESS角度故障且转速高于无感可用阈值角度源切换、限制力矩
任意 → FAULT故障置位先关管，再清积分、记录
FAULT → READY可恢复故障清除 + 上层复位请求重新自检
READY ⇄ CALIB标定模式请求（XCP，仅开发 / 产线权限）运行标定流程

第四部分：嵌入式实现步骤

  1. 定义 FOC_tst（运行数据，导读中给出并逐章扩充）、FOC_CAL_tst（标定量，可放在独立内存段便于 XCP 页切换）。
  2. 算法函数签名统一：void Foc_X_Run(const IN_tst*, OUT_tst*, STATE_tst*)，便于 PC 单元测试。
  3. 状态机在 1 ms 任务中运行；主中断只读取状态决定执行哪些模块。
  4. 每个转移写测试用例，包括非法请求（如 FAULT 中请求 RUN）。

第五部分：仿真与波形预期

  • 上电时序：INIT → OFFSET_CAL（约 0.1 s）→ READY，记录状态变量与 PWM 使能信号。
  • 故障注入：任意运行态 → FAULT 时 PWM 立即关闭，状态与故障码正确。

第六部分：EPS 案例实现

typedef enum { FOC_ST_INIT, FOC_ST_OFFSET_CAL, FOC_ST_READY, FOC_ST_RUN_TORQUE,
               FOC_ST_RUN_SENSORLESS, FOC_ST_CALIB, FOC_ST_FAULT } FOC_State_ten;

void Foc_Sm_1ms(void)
{
    switch (gFoc.state) {
    case FOC_ST_INIT:
        if (Pwr_IsStable() && (labs(gFoc.spdRpmFilt) < 30)) { Pwm_DisableAll(); gFoc.state = FOC_ST_OFFSET_CAL; }
        break;
    case FOC_ST_OFFSET_CAL:
        if (gFoc.offsetDone) { gFoc.state = Diag_AnyFault() ? FOC_ST_FAULT : FOC_ST_READY; }
        break;
    case FOC_ST_READY:
        if (gApp.enableReq && !Diag_AnyFault() && Angle_IsValid()) {
            FOC_PiResetAll();
            FOC_CurrentLoop_PresetFromSpeed(gFoc.wePu_q15);   /* 旋转中使能：预置反电动势前馈 */
            Pwm_EnableAll();
            gFoc.state = FOC_ST_RUN_TORQUE;
        } else if (gApp.calibReq) { gFoc.state = FOC_ST_CALIB; }
        break;
    case FOC_ST_RUN_TORQUE:
        if (!gApp.enableReq) { Pwm_DisableAll(); gFoc.state = FOC_ST_READY; }
        else if (!Angle_IsValid() && Obs_IsUsable()) { Angle_SelectSource(ANG_SRC_OBS); gFoc.state = FOC_ST_RUN_SENSORLESS; }
        break;
    case FOC_ST_FAULT:
        if (Diag_Recoverable() && gApp.resetReq) { gFoc.state = FOC_ST_READY; }
        break;
    default: break;
    }
    if (Diag_AnyFault() && (gFoc.state != FOC_ST_FAULT)) { FOC_EmergencyOff(Diag_FirstCode()); }  /* C12 */
}

第七部分：高频调试问题

【高频故障】电机转动中使能，瞬间大电流
现象
车辆行驶中 EPS 复位后重新使能，冲击明显。
可能根因
使能时 PI 输出为 0，但反电动势存在，相当于给电机加了一个「反电压」。
排查
记录使能瞬间转速、vq、iq。
修复
按当前转速预置 vq = ωe·ψf（飞车启动）。
验证
不同转速下使能电流平滑。
【高频故障】FAULT 后自动恢复反复触发
现象
间歇性故障导致电机频繁启停。
可能根因
恢复条件过松，无次数限制。
排查
故障记录中的恢复次数。
修复
恢复次数上限、严重故障锁存到下次上电。
验证
间歇故障注入表现符合设计。
易错点：算法模块直接访问寄存器
现象
算法无法在 PC 上测试，换 MCU 要改算法。
根因
分层被破坏。
排查
代码依赖分析。
修复
HAL 接口隔离。
验证
算法模块 PC 单元测试通过。

第八部分：工程踩坑

  • 状态判断分散在多个模块：难以分析所有转移；状态机集中在一个函数。
  • 标定模式在量产软件中可被意外触发：需要权限保护（Seed&Key / 产线模式）。
  • 全局结构体被多个任务写：明确每个字段的唯一写者。
